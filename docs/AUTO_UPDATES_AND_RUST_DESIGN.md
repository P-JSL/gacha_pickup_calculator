# 자동 갱신 및 Rust 설계 원칙 (v1.0.3 기준)

## 적용 범위

- **게임 4종의 데이터 갱신**: 앱 실행 시 GitHub 저장소의 main 참조 SHA를 확인하고, 동일 커밋의 catalog_data.tsv, signature_pairs.tsv, Image/SHA256SUMS.txt를 한 세트로 받습니다.
- **이미지 갱신**: 새 버전에서 SHA-256이 변경된 PNG만 받습니다. 형식(PNG), 파일 크기(최대 512 KiB), 해상도(최대 256×256), 실제 디코딩 가능 여부를 검사합니다.
- **캐시**: 검증된 데이터와 이미지를 revision별 개인 캐시에 보관하고, 오프라인에서는 마지막으로 검증된 캐시 또는 배포 ZIP의 내장 데이터를 사용합니다.
- **프로그램 버전 확인**: GitHub 최신 릴리즈 태그를 확인해 앱 Settings에 표시하고 설치 페이지를 제공합니다. **현재 자동 EXE 교체/무인 설치는 제공하지 않습니다.** 검증되지 않은 실행 파일 다운로드·실행을 자동화하지 않습니다.
- **실행 시 확인**: GitHub API 및 `raw.githubusercontent.com` HTTPS 접근이 가능하고 시스템에 `curl`이 설치되어 있어야 합니다. 네트워크 오류 시 앱과 확률 계산은 계속 작동합니다. 다운로드 URL은 승인된 파일/커밋 경로로 제한하며 사용자 `.curlrc` 설정은 무시합니다.
- **실패 동작**: 새 데이터의 유효성이 미달하면 해당 세트를 폐기합니다. 기존 캐시/내장 카탈로그, 선택값과 확률 계산은 유지합니다.

## 신뢰 경계

| 계층 | 입력 | 방어 |
|---|---|---|
| 업데이트 주소 | 고정된 GitHub 저장소 API와 Raw URL | 쉘 미사용, 고정 HTTPS 출처, 리다이렉트 거부, 타임아웃, 다운로드 크기 제한 |
| GitHub 커밋 | `main`의 40자리 SHA, REST 서명 정보 | GitHub가 `verified=true`·`reason=valid`로 표시한 커밋 및 예상 게시자·커밋터 확인. GitHub 자체 침해에 독립적이지 않음 |
| 데이터 파일 | 커밋 SHA 기준 TSV 세트 | ID/게임/분류/중복/5★ 전용 장비 관계 및 전체 이미지 목록 검증 |
| 이미지 | 해당 SHA의 PNG | 승인된 경로와 SHA-256 비교, PNG 파서 검증, 크기 및 픽셀 제한 |
| 활성 카탈로그 | 검증이 완료된 불변 스냅샷 | 단일 RwLock 포인터 교체; I/O 중 잠금 없음 |
| 기존 패키지 | 릴리즈에 포함된 SHA 매니페스트 | 변경 없는 내장 이미지 재사용, SHA 변경 이미지만 별도 캐시 |
| 오류와 예외 | 네트워크 장애 / RwLock poison | Result 오류 전파, poison 상태 복구 우회 금지, 기존 데이터 사용 |

### Rust idioms

- **Parse, Don't Validate**: 네트워크 TSV는 VerifiedBundle 생성 경로를 통과해야만 활성 카탈로그로 게시할 수 있습니다.
- **Ownership/Borrowing**: 갱신 스레드가 완성된 번들을 소유하고 UI가 수신합니다. GUI는 변경 불가능한 Arc 스냅샷을 공유합니다.
- **Composition over inheritance**: 카탈로그/업데이트 네트워크/이미지 무결성/확률 엔진의 역할을 분리합니다.
- **Explicit errors**: Result 기반 실패 처리. 정상적인 다운로드 오류는 RwLock poison과 구별합니다.
- **Poisoning**: std::sync::RwLock은 쓰기 잠금 중 panic 발생 시 poison됩니다. 보호 데이터가 손상됐을 수 있으므로 into_inner()로 강행 복구하지 않습니다.
- **효율화**: 확률 DP의 상태 배열은 반복 단계마다 재사용하고, 소프트 천장 확률 및 NTE Arc 자연 분포를 사전 계산/캐시합니다. GUI 이미지 로딩은 4개 스레드에서 진행되며 구세대 결과가 새 이미지에 섞이지 않도록 generation으로 분리합니다.
- **정적 디스패치 우선**: 런타임의 단일 업데이트 구현에는 불필요한 dyn Trait/Box 추상화를 도입하지 않습니다.

## 공식 출시일 / 데이터 출처의 제한

앱은 업데이트 내용을 **GitHub main에서 검증·반영된 스냅샷**으로부터 자동 수신합니다. 이는 게임사의 공개/정식 출시 날짜 자체를 실시간 발견하는 기능과 다릅니다. 공식 발표가 있었다고 해서 모든 캐릭터 ID, 전용 광추/무기/아크/레코드, 배너 유형, 실제 초상화가 공개되는 것은 아닙니다. 원본 서비스마다 데이터 제공 방식과 라이선스가 다르므로 자동으로 확인되지 않은 관계를 생성하지 않습니다.

- 공식 발표 또는 확인된 소스 데이터를 카탈로그로 등록하고, 전용 장비 연결 및 이미지 자료를 검증한 후 main에 반영해야 이용자 앱에 자동 전파됩니다.
- 사진이 없거나 매핑이 확인되지 않은 항목은 임의의 다른 아이템과 연결하지 않습니다. 미확정 버전/유출 자료를 출시 확정으로 오인하지 않도록 관리해야 합니다.
- 상위 저장소의 변경 감지, 공식 발표일 추적, 무인 업데이트 설치는 이 문서에 설명한 앱 내 데이터 전파 기능과 별개의 후속 자동화 대상입니다.

## 검증 목록

1. 오프라인 최초 실행: 내장 카탈로그 및 이미지 유지.
2. 새 커밋의 일관된 TSV 및 PNG: 이미지 해시가 다른 항목만 다운로드하고 전체 검증 후 활성화.
3. 빈 데이터·누락 매니페스트·미등록 ID 참조·중복 ID·잘못된 SHA: 거부하고 이전 데이터 유지.
4. 이미지 파일 위조·PNG 대신 SVG/HTML: 로딩 거부.
5. 현재 다운로드 진행 중 이전 캐릭터 사진 작업의 늦은 응답: generation 검사로 폐기.
6. 실행 중 앱 업데이트 발견: Settings에 릴리즈 안내, 바이너리 자동 실행 없음.
7. 기존 전체 Rust 단위 테스트 및 Clippy, Linux/Windows 빌드, 이미지 보안 검사.

**주의**: 소스 호스트의 허위 매핑 및 악성 커밋을 SHA-256만으로 탐지할 수는 없습니다. SHA는 받은 파일의 동일성을 보장할 뿐 공식성·저작권·인물 외형의 정확성을 증명하지 않습니다.

## 배포/런타임 이미지 갱신의 차이

- **일반 Rust CI 및 릴리즈:** 이미 저장소에 포함된 `Image/` PNG를 검증·해시 대조·ClamAV 검사하여 패키징합니다. 매 릴리즈마다 외부 자산 원본을 다운로드하거나 재인코딩하지 않습니다.
- **관리자 수동 갱신:** `refresh-artwork.yml`을 명시적으로 실행한 경우에만 감사 대상 원본으로부터 수집 및 정규화된 후보 이미지를 만들고 검토를 거쳐 채택합니다.
- **사용자 앱:** 사용자가 최신 카탈로그를 확인할 때 **이 저장소의 승인된 커밋**에서 새 PNG를 HTTPS로 가져올 수 있습니다. 원본 게임 출처 URL을 임의로 따라가지 않습니다.
- **프로그램 실행 파일:** 최신 릴리즈 안내만 제공하며 사용자의 PC에 있는 EXE 파일을 자동 교체하지 않습니다.

**독립 키 서명 미지원:** GitHub REST의 검증 상태는 GitHub 자체가 관여한 인증 결과입니다. 저장소 소유자 계정이 침해되면 서명된 악성 커밋도 가능하므로, 별도 오프라인 키 검증이 구현됐다고 해석하지 마십시오. [공급망 운영 경계](SECURE_RELEASE_v1_0_3.md).
