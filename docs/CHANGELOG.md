# 변경 이력 · Gacha Pickup Calculator

현재 릴리즈는 **v1.0.3**입니다. 구버전 개별 문서와 스크린샷 대신 과거 배포 상세는 [GitHub Releases](https://github.com/P-JSL/gacha_pickup_calculator/releases)에서 확인할 수 있습니다.

## 버튼 클릭 기반 계산·GUI 실시간 감지 (2026-11-07, v1.0.3 프로그램 코드 수정, 릴리즈 유지)
- 기본 실행·게임 선택·입력 변경 및 기존 CI 환경변수로 자동 계산하던 경로 제거. 완료된 입력으로 `Run Simulation`을 클릭할 때만 백그라운드 계산 시작.
- 완료 이벤트는 클릭 직후 발생한 계산의 세대와 게임에 연결하고, 이전 계산 응답·입력 변경·작업 실패를 구분하여 CI에서 잘못된 결과를 촬영하지 않도록 강화.
- `scripts/capture_readme_screenshots.sh`가 화면의 실제 Run 버튼을 찾아 클릭하고 완료 이벤트를 실시간 확인하도록 변경. 게임별 11초 고정 대기 제거 및 Python 단위 테스트 보강.
- 기존 수학 모델·추정 알고리즘·게임 규칙·데이터·서명·배포 자산 변경 없음. 변경 사항은 검증된 신규 릴리즈를 만들기 전까지 기존 v1.0.3 다운로드에 반영되지 않음.

## 테스트·빌드 경로 병렬화 (2026-11-07, 버전 v1.0.3 유지)
- Windows·Linux의 `Verify` 작업에서 Release 빌드를 분리하여, 기존 단위 테스트·Clippy와 OS별 Release 빌드가 **동시에** 실행되도록 변경.
- `Capture latest-character GUI for README`의 선행 조건을 Linux 실행 파일 준비만으로 축소. Windows 테스트·빌드 완료와 무관하게 실제 GUI 캡처 시작.
- 새 릴리즈는 기존 Verify 2종에 Linux/Windows Build 2종, RustSec, 성능, 이미지 검사 및 GUI 캡처의 성공을 요구. Windows Authenticode 및 기존 Sigstore 검증 경로 유지.
- 원본 Rust 소스·게임 데이터·릴리즈 파일 변경 없고, 신뢰되지 않은 공용 빌드 캐시 도입 없음.

## 장시간 보안·성능 작업 병렬화 (2026-11-07, 버전 v1.0.3 유지)
- Linux `Verify`에 순차적으로 묶였던 RustSec(약 2분 56초)와 Release 성능 테스트(약 1분 39초)를 독립적인 병렬 Job으로 분리.
- 이미지 매니페스트 정합성/배포 자산 준비를 ClamAV 패키지 설치·바이러스 검사(약 7분 10초)와 분리. GitHub Ubuntu 공식 미러 우선 사용.
- GUI 캡처는 Linux 실행 파일 준비만 기다리고 RustSec·성능·ClamAV 병렬 검사 결과는 신규 버전의 최종 서명/배포 게이트에서 집계.
- 기존 v1.0.3 바이너리·릴리즈·게임 데이터·Rust 소스 변경 없음. 워크플로 요구/스킵 및 관리자 Ruleset 항목 문서 최신화.

## 문서·CI 운영 정비 (2026-11-07, 버전 v1.0.3 유지)
- `README.md`를 설치·정확성·재화·자동 업데이트·서명 검증·성능 실측 중심으로 재정리하고, 구버전 기록은 각 감사 문서 및 릴리즈 노트로 분리.
- 일반 배포 CI에서 외부 자산을 매번 수집·재인코딩하는 것처럼 보였던 설명과, 앱이 실행 중 외부 이미지를 절대 요청하지 않는다는 상충된 문구를 정정.
- 문서만 변경되면 문서 계약 검사만 수행하도록 GitHub Actions Job별 변경 범위 판별 추가. Rust·이미지·GUI·신규 버전은 해당 검사만, CodeQL은 변경 언어만 분석(주간/수동 전체 분석은 유지). 필수 매트릭스 체크 이름을 보존하고 `main`의 배포 실행은 자동 취소하지 않음.
- v1.0.3의 Windows 실행 파일은 Authenticode 미서명이며, GitHub Ruleset/Immutable Releases가 미적용 상태임을 명시. 기존 릴리즈 자산과 프로그램 코드는 변경하지 않음.
