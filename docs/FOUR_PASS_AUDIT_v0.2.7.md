# v0.2.7 · 전체 코드 4회 순환 검토 및 최종 재검토

> 검토 기준: v0.2.6 병합 커밋 `78529181656b5f055c65fb5afb5fd64474c37e7f`.
> 범위: Rust 확률/환급/실측/카탈로그/업데이트/보안/GUI 모듈, TSV 매핑, 이미지 SHA-256 매니페스트, Python 자산·CI 검사기, Cargo.lock 및 GitHub Actions. 검토는 정적 분석과 자동화 테스트를 결합한 범위이며 외부 실제 게임 계정 및 모든 가능한 3자 공급망 취약점의 완전 검증을 뜻하지 않습니다.

## 1차 · 확률 및 경계 정합성

**검토**: `src/lib.rs`의 Standard/FeaturedCounter/NTE Arc 배너별 최초 달성 확률 분포, 천장, 100% 확정 분위수 및 결합 분포의 경계값을 재검토했습니다.

**수정**: NTE Arc의 분포 생성 범위를 `(target_copies × 8 - current_pity) × 10`에 맞춰 조정하여 확정 이후 도달 불가능한 빈 꼬리를 제거하고, `max_additional_pulls`에서 포화 산술을 적용했습니다. 비정상 천장 입력과 빈 분포 결합의 오류 경로를 보완했습니다.

**추가 검토**: 기존 천장 스택 0~7·목표 장수별 최대 10연 횟수, PMF/CDF의 정규화 및 종료 경계를 테스트했습니다. 0%/100% 분위수와 입력 크기 제한도 확인했습니다.

## 2차 · 업데이트 캐시, 로컬 파일 및 실측 데이터

**검토**: `src/runtime_updates.rs`, `src/security.rs`, `src/catalog.rs`, `src/observations.rs`를 대상으로 데이터 파일 신뢰 경계, 로컬 파일 사이즈, UTF-8, 심볼릭 링크, 통계 입력 스키마를 검토했습니다.

**수정**: 오프라인 캐시 읽기의 상한/파일형식/UTF-8 검증, 임시 캐시 파일의 `create_new`·`sync_all`, CSV 위험집합·검열 열의 누락과 중복·혼합 헤더 거부를 추가했습니다.

**추가 검토**: 손상된 캐시, 크기 초과, 비UTF-8, 심볼릭 링크 및 불완전한 생존분석 CSV 회귀 테스트를 추가했습니다. 코드에서 외부 응답을 무조건 신뢰하는 대신 기존 매니페스트 검증 조건을 유지했습니다.

## 3차 · 환급 재사용 및 계정 기본값

**검토**: `src/feedback.rs`, `src/games.rs`, `src/main.rs`, `src/dashboard_ui.rs`의 보유 캐릭터·장비, 전용권/재화, 환급 반복 사용, 직접 API 호출, 새로운 계정 상태를 점검했습니다.

**수정**: 환급 포인트·레코드 디스크의 포화 산술과 Arc 반환 포인트 합산형을 명확히 했습니다. 사용자가 보유 정보를 입력하기 전 스타레일에 임의로 부여되던 캐릭터 천장 3회/픽업 확정을 0회/미확정으로 수정했습니다. 과거 3회/확정 테스트는 개별 fixture로 보존했습니다. `feedback::estimate`가 UI 이외 직접 호출될 때도 잘못된 확률 배너를 먼저 거부하여 무한 시뮬레이션을 방지했습니다.

**추가 검토**: 신규 계정 상태, 과거 독립 DP 기준, 잘못된 확률 입력, 0% 분위수, 큰 환급값과 캐릭터/장비 별도 자금 출처 회귀 테스트를 점검했습니다. 스타레일 기본값 수정은 신규 기본 계산 결과를 의도적으로 변경하며, 사용자가 직접 입력한 천장/확정/기보유 정보를 덮어쓰지 않습니다.

## 4차 · CI, 배포·공급망 및 문서 정합성

**검토**: `.github/workflows/`, `scripts/`, `Cargo.toml`, `Cargo.lock`, `README.md`, `docs/`, 릴리즈 패키징을 검토했습니다.

**수정**: 과거 작업을 이미 마친 뒤에도 자체 파일 변경 시 GitHub Actions가 `main`에 쓰기를 시도할 수 있는 일회성 워크플로 3개를 제거했습니다. 최신 릴리즈 외의 구버전별 소스 트리 노트는 릴리즈 페이지에 이력으로 유지하고 링크/문서를 정리했습니다.

**추가 검토**: 읽기 전용 CI와 이미지 클린업·매니페스트 검사·Windows/Ubuntu 빌드의 실행 순서, 릴리즈 파일 버전·해시·캡처 생성, 불필요한 실행권한 최소화를 확인했습니다.

## 5차 · 최종 독립 검토 및 검증 기준

- 신규 수정이 기존 4개 게임의 보유권 구분, 환급 재투입, 공식 확률 모드 기본값, 기존 외부 API를 유지하는지 최종 대조합니다.
- PR CI에서 Windows/Ubuntu `cargo test --locked --all-targets`, `cargo clippy --locked --all-targets -- -D warnings`, 빌드, RustSec, 이미지 검증/ClamAV 및 실제 GUI 스크린샷을 **모두 성공**해야만 병합합니다.
- `main` 병합 후 별도 릴리즈 CI 재실행과 v0.2.7 배포 자산 5개의 업로드·해시·태그 커밋 일치를 확인해야 완료로 판정합니다.
- 실제 게임 공식 모집 방식·천장·미공개 소프트 천장·72칸 보드의 정확한 위치 전이와 계정별 4성 중복/상점 환급은 알려진 가정을 벗어나면 추정치를 유지합니다. 외부 계정 검증 없이 정확하다고 단정하지 않습니다.
- 로컬 파일을 같은 사용자 권한으로 바꿀 수 있는 악성 프로그램, 신뢰된 상위 저장소 공급망, Windows 파일 교체의 POSIX 대비 원자성 차이, 제3자 이미지 라이선스는 **남은 제한**입니다. 보안 검사 성공을 취약점 제로로 해석하지 않습니다.
