# 보안 및 패키징 검토

검토 대상: Rust 소스 전체(`src/`), 로컬 카탈로그/매핑/해시 매니페스트, Python 자산·검증 스크립트(`scripts/`), GitHub Actions(`.github/workflows/`), Cargo 의존성 그래프 및 문서 연결.

이 문서는 기존 이미지 무결성 검토와 v0.2.7의 네 차례 코드 검토를 포함한 방어 조치를 요약합니다. 테스트 성공이 모든 보안 결함의 부재를 증명하지는 않습니다. 변경 근거 및 제한사항은 [4회 검토 보고서](FOUR_PASS_AUDIT_v0.2.7.md), 캐릭터·장비 데이터 검증 범위는 [카탈로그 검증 보고서](CATALOG_AUDIT.md)를 참조하세요.

## 보안 검증 방법

```bash
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo audit
python3 scripts/verify_embedded_assets.py
python3 scripts/verify_release_contract.py
```

`scripts/build_offline_images.py`는 **관리자가 명시적으로 실행하는 이미지 수집 전용**이며 외부 네트워크가 필요합니다. 일반 CI·릴리즈는 이미 저장소에 고정된 PNG를 검증·스캔·패키징할 뿐, 이미지를 매번 재수집하거나 재인코딩하지 않습니다. **테스트 통과가 보안 취약점 부재를 증명하지는 않습니다**. 소프트웨어 구성요소, 바이너리 서명 여부, 공급망 자산 사용권 및 사용자 기기의 보안 수준은 별도로 관리해야 합니다.

## 향후 유지보수 주의

- 이미지 소스 변경 시 `approved_source_url` 및 Rust 허용 목록을 동시에 변경하고, 출처 소유권과 배포 가능 여부를 확인합니다.
- `src/signature_pairs.tsv`에 새 쌍을 등록할 때 해당 시점 공식 캐릭터·무기 배너를 확인하고 **ID 중심으로** 등록합니다. 이름 유사도나 목록 순서로 자동 매칭하지 않습니다.
- 사진이나 장비의 오류 신고 시 ID, 게임, 원본 자산 URL, 기대 이름 및 출처를 기록합니다. 단순 이미지 검색 유사도만으로 교체하지 않습니다.
- `cargo audit` 및 이미지 스캐너 결과는 출시 전 확인하되, 새로운 외부 공급망 보안 권고가 나올 수 있으므로 정기 점검이 필요합니다.

## v1.0.2 후속 보안 강화

- 바이너리 전용 모듈의 `pub` 사용을 `pub(crate)`로 한정하고, CI 정적 검사로 새 public 노출을 차단합니다. 단, Public GitHub 저장소의 소스 코드는 누구나 볼 수 있습니다.
- HTTPS 갱신 경로를 승인된 GitHub 커밋 SHA·TSV·해시 파일·PNG 경로로만 좁혔습니다. `curl --disable`을 첫 옵션으로 지정하여 사용자 `.curlrc`의 강제 리다이렉트·TLS 우회 등 전역 옵션이 개입하지 않도록 합니다.
- 언어 설정 저장은 원자적 스테이징을 사용하며, 기존 심볼릭 링크 및 일반 파일이 아닌 출력 대상을 거부합니다. Windows의 기존 파일 제거/교체 사이 짧은 비원자 구간은 별도 제한입니다.
- CSV 헤더 상한을 64열로 지정하고 중복 검사 O(h) 해시 인덱스를 적용했습니다. 카탈로그 전용 장비 연결 대상 탐색도 O(n+p) 기대 해시 조회로 바꿨습니다.
- Git 추적 파일의 고위험 비밀키·환경설정 파일명 패턴을 CI에서 거부합니다. 이 검사는 내용 기반 비밀 탐지, 이미 커밋된 과거 기록 제거, 계정 침해 방지까지 보장하지 않습니다.
- 잔여 위험과 필요한 관리자 설정은 [보안 경계 문서](SECURITY_BOUNDARY_V1_0_2.md)를 참조하십시오.

## v1.0.3 공급망 및 코드 보안 강화

- GitHub OIDC/Sigstore 서명 기반 릴리즈 provenance를 게시 전 생성·검증하고, Windows 서명은 실제 Authenticode 인증서가 있는 경우에만 시행합니다. SHA-256 및 서명은 다른 신뢰 모델이므로 혼동하지 않습니다.
- 실행 파일을 자동 교체하지 않는 기존 업데이트 정책을 유지하면서, 원격 데이터의 GitHub 검증 커밋·예상 계정·SHA를 확인하는 추가 방어를 배치합니다. 저장소 관리자가 공격받으면 Github가 검증한 악성 커밋도 만들어질 수 있으므로 완전한 방어가 아닙니다.
- 공개 Rust 확률 엔진에 `#![forbid(unsafe_code)]` 적용. Rust·Python·GitHub Actions의 CodeQL 보안 스캔 추가.
- 대규모 밀집 분포와 분위수 계산 경로의 실측 benchmark를 Linux release 최적화 빌드로 실행하여 실제 성능 수치를 확보합니다.
- `main` 브랜치 보호와 Immutable Releases는 GitHub 저장소 관리 권한으로 별도 설정해야 하며, 미적용 상태를 '적용 완료'로 표시하지 않습니다.

공식 문서 및 운영 절차: [v1.0.3 보안 배포](SECURE_RELEASE_v1_0_3.md).

## 문서·워크플로 정비 (v1.0.3 릴리즈 유지)

- 최신 README와 설계·보안 안내의 기준을 동일한 정식 릴리즈 `v1.0.3`으로 맞추고, 이전 버전의 감사 문서는 **해당 버전 기준 과거 검증 기록**으로 구분합니다.
- 기존 릴리즈의 내부 `README.txt`에는 앱이 이미지 요청을 하지 않는다는 오래된 문구가 있었지만, 실제로는 승인된 `main` 커밋에서 업데이트 PNG를 HTTPS로 받을 수 있으므로 안내를 정정했습니다. 기존 바이너리/릴리즈 자산은 수정하지 않았습니다.
- CI는 문서만 수정할 경우 문서 링크·버전 계약만 확인하고, 실제 소스·이미지·GUI·신규 버전 변경 때에는 필요한 보안 검사를 실행합니다. 변경 경로 확인 실패 시 안전하게 전체 검사를 수행합니다.
- Ruleset·Immutable Releases·Windows Authenticode의 관리자 미적용 상태를 명확히 유지합니다. 실제 보호 설정이나 개인키 관리가 자동으로 완료되는 것은 아닙니다.
