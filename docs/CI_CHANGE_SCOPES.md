# GitHub Actions 변경 범위별 검증 정책

**검증 기준: v1.0.18 (배포 계약은 이후 변경 시 재확인)** · [워크플로](../.github/workflows/rust.yml)

## 목적

문서만 정리할 때 불필요한 대규모 Rust 빌드·이미지 검사와 중복 릴리즈가 실행되지 않도록 하고, 실행 코드·배포 변경에 대해서는 관련 검증을 유지합니다.

## 입력별 실행 원칙

| 변경 범위 | 실행 원칙 |
|---|---|
| README·docs·라이선스·릴리즈 노트만 변경 | 문서 링크·릴리즈 계약 검사. 기존 릴리즈는 재게시하지 않음 |
| Rust/확률/환급 소스·의존성 변경 | Windows/Linux 테스트 및 Clippy. 필요 시 성능·보안·빌드 게이트 |
| 이미지·카탈로그/매핑 변경 | 이미지 체크섬·카탈로그 정합성 검사, 필요 시 실제 GUI 스크린샷 |
| UI·계산 트리거 변경 | Rust 테스트 및 화면 구동·시뮬레이션 실행 완료 기반 캡처 |
| 새 버전의 정식 릴리즈 | 두 운영체제 빌드·검증, RustSec·성능·이미지 검사, GUI 캡처, 자산/해시/출처 증명 후 게시 |

검증 범위 판별이 불가능하면 필요한 게이트를 생략하지 않고 전체 검사를 수행합니다. OS별 `Verify`와 언어별 CodeQL Job 이름을 유지하여 저장소 보호 규칙에 설정된 상태 검사를 Pending으로 남기지 않도록 합니다.

## 수동 시뮬레이션·GUI 캡처

사용자 입력 변경으로 계산을 자동 시작하지 않습니다. **Run Simulation** 클릭 시 해당 입력 스냅샷·세대만 Worker로 전송합니다. GUI CI는 실제 위젯을 클릭하고 동일 세대의 `STARTED/COMPLETED/FAILED` 완료 상태를 확인한 다음 화면 캡처를 검사합니다.

CI 캡처용 관찰 기능은 `GACHA_CI_SIMULATION_EVENTS=1`에서만 활성화되고, 사용자의 계산을 대신 자동 실행하지 않습니다. 캡처는 완료 이벤트를 기다리며 고정 대기만으로 성공 판정을 하지 않습니다.

## 병렬화·릴리즈 안전 장치

- Windows/Linux 빌드와 테스트를 분리하고 RustSec, 성능, PNG 무결성, 이미지 스캔을 독립 실행합니다.
- Linux GUI 캡처는 Linux 실행 파일 빌드 완료 후 시작합니다.
- 정식 릴리즈는 모든 필요한 검증이 성공해야 진행하며, 태그가 이미 존재하는 경우 무단으로 덮어쓰지 않습니다.
- 사용자용 릴리즈 자산 **4종**(.exe, Windows ZIP, 화면 캡처 ZIP, SHA256SUMS)을 확인하고 GitHub 출처 증명을 검증한 뒤 Draft를 게시합니다. 중복 소스 ZIP은 별도로 업로드하지 않습니다. GitHub 기본 소스 아카이브는 별개입니다.
- Windows ZIP의 `log/` 폴더와 내장 이미지 매니페스트·실제 이미지 SHA를 검증하며, 이전 실행의 `log/session.log`는 릴리즈에 포함하지 않습니다.
